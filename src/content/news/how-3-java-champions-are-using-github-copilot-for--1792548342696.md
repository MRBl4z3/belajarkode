<p class="wp-block-paragraph">Here are the tips they shared with us.</p>

<h2 class="wp-block-heading" id="vlad-mihalcea">Vlad Mihalcea</h2>



<p class="wp-block-paragraph">GitHub profile: <a href="https://github.com/vladmihalcea">@vladmihalcea</a></p>



<p class="wp-block-paragraph"><strong>How has GitHub Copilot helped you recently?</strong></p>



<p class="wp-block-paragraph">I&rsquo;ve been using it to analyze, design, and implement various features in both Hypersistence Utils and Hypersistence Optimizer.</p>



<p class="wp-block-paragraph">For example, I&rsquo;ve been wanting for a long time to develop a web application that provides Optimizer event history so we can see how performance improvement efforts are materializing in application performance. Before AI, I kept postponing this task because it would have taken me weeks to develop. But using Copilot is like having a new team member, so I used it to create an app that will ship in the next version of Hypersistence Optimizer. Instead of weeks, this task took just two days to implement.</p>



<p class="wp-block-paragraph"><strong>What&rsquo;s your typical usage? Are you using GitHub Copilot as an IDE plugin or the GitHub Copilot app?</strong></p>



<p class="wp-block-paragraph">I use GitHub Copilot in IntelliJ IDEA because it&rsquo;s convenient to run while reviewing source code or during a debug session.</p>



<p class="wp-block-paragraph">It&rsquo;s very useful as a code assistant, and it helps me speed up both investigations and building prototypes for features that need validation.</p>



<p class="wp-block-paragraph">I still review the plans and the code that is generated by AI since their goal is to improve my productivity, not replace me entirely. While AI provides the right answer in many situations, there are still times when the response is not satisfactory and requires my intervention.</p>



<p class="wp-block-paragraph"><strong>Can you share some tips and best practices? For example, which skills are you using?</strong></p>



<p class="wp-block-paragraph">I created my own skills so that whatever text Copilot generates looks like something I wrote by hand.</p>



<p class="wp-block-paragraph">This skill captures my voice from 65 of my published articles, so a draft comes back sounding like my blog instead of like a language model. This is really useful when generating documentation for this project, since it lets the LLM learn from 12 years of blogging and provide examples that follow the same principles, such as expressiveness, testability, and simplicity.</p>



<p class="wp-block-paragraph">Throughout my career as a software engineer, I&rsquo;ve learned that we spend far more time on code maintenance than on creating it. Therefore, because maintenance and stability are critical for existing products, I developed skills that help AI mimic existing code practices in accordance with the principle of least astonishment.</p>



<p class="wp-block-paragraph">One tip is to change the model type based on the type of operation. For thorough thinking, I use Opus with the 1 million context window and Extra High or Max reasoning. However, for simpler tasks, such as generating reports, release notes, or verifying documentation, I use lighter models that consume fewer tokens.</p>



<h2 class="wp-block-heading" id="patrick-baumgartner">Patrick Baumgartner</h2>



<p class="wp-block-paragraph">GitHub profile: <a href="https://github.com/patbaumgartner">@patbaumgartner</a></p>



<p class="wp-block-paragraph"><strong>Your work involves coaching teams. What is your approach?</strong></p>



<p class="wp-block-paragraph">A lot of my work happens while the normal business still has to keep running. You cannot stop everything for six months to &ldquo;transform.&rdquo; We usually start by solving immediate problems together, understand where the team currently stands, define where we want to go and how we will know that we are improving, and then move there step by step.</p>



<p class="wp-block-paragraph">Depending on the situation, that can mean Software Craft practices such as TDD, refactoring, continuous delivery and XP; architecture and modularisation with Spring Boot, Spring Modulith; Spring Security; optimising Java and Spring Boot applications for containers; or increasingly, agentic engineering.</p>



<p class="wp-block-paragraph">The important part for me is that I work <em>with</em> the team. We make decisions together. I don&rsquo;t want a team to become dependent on me. Ideally, after some time they no longer need me except perhaps as a sparring partner.</p>



<p class="wp-block-paragraph">And maybe that explains why I find this new generation of AI tools so interesting: I like working with people, learning, experimenting, and solving problems. AI gives us another very powerful tool for doing exactly that.</p>



<p class="wp-block-paragraph"><strong>Can you share a good story about how GitHub Copilot has helped you recently?</strong></p>



<p class="wp-block-paragraph">There are actually three very different examples that changed how I think about working with GitHub Copilot.</p>



<p class="wp-block-paragraph"><strong>Let&rsquo;s start with the first one.</strong></p>



<p class="wp-block-paragraph">One was a migration of around 900 teaching slides across 15 presentations from Reveal.js to Marp. These were not simple slides. Many contain code, animations, and even interactive examples where I can change JavaScript live while teaching. More importantly, the presentations had already been battle-tested with students. The flow worked. Losing one small piece could break the story I use in the classroom.</p>



<p class="wp-block-paragraph">Doing that migration manually would probably have taken me a week or more&mdash;and realistically, I might simply have avoided doing it because it was such tedious work.</p>



<p class="wp-block-paragraph">With Copilot, I approached it differently. We first analysed the existing material, defined the target, created a migration plan, established constraints, provided examples, and defined what had to remain intact. Then we worked from the big structural changes down into the details.</p>



<p class="wp-block-paragraph">The really important part was verification.</p>



<p class="wp-block-paragraph">We generated screenshots of the Reveal.js and Marp versions and compared them visually and algorithmically. We built a small application where I could run both slide decks next to each other to verify animations manually. We even compared the generated PDFs.</p>



<p class="wp-block-paragraph">That meant the agent did not just say, &ldquo;Migration complete.&rdquo; We had evidence.</p>



<p class="wp-block-paragraph">The entire migration took me roughly eight to ten hours. I still owned the content, the teaching intent, and every meaningful change. Copilot could fix a typo automatically, but if content, versions, dates or meaning changed, that was something we discussed.</p>



<p class="wp-block-paragraph">For me, that experience reinforced an important principle: <em>delegate execution, not responsibility.</em> I own the result.</p>



<p class="wp-block-paragraph"><strong>Can you share the second example?</strong></p>



<p class="wp-block-paragraph">A second example came from building a terminal UI application with Tamboui. It initially worked perfectly in Linux under WSL, and I had completely forgotten that somebody might run it directly in Windows CMD or PowerShell.</p>



<p class="wp-block-paragraph">And then a real user did.</p>



<p class="wp-block-paragraph">They discovered that the Enter key was simply ignored in some forms. That is another principle I strongly believe in: ship software early, because you learn from how people actually use it.</p>



<p class="wp-block-paragraph">We used Copilot to turn that feedback into reproducible UI tests. On Linux, Copilot was navigating the application with tmux. Through working with it, I learned about psmux and could execute similar flows in PowerShell. We reproduced the problem, created a local fix, traced the real problem into Tamboui, and I submitted the upstream fix, which was merged.</p>



<p class="wp-block-paragraph">During this work, the test descriptions themselves became too large for the available context. So I asked Copilot to help me redesign the way the tests were represented. Instead of verbose tables containing identifiers, names and repeated descriptions, it proposed a much more compact arrow notation: step &rarr; step &rarr; input, with additional information only where it was critical.</p>



<p class="wp-block-paragraph">That surprised me. We were not just using AI to execute information; we were working together on <em>how information should be represented for execution</em>. It did not have to be maximally human-friendly. It had to preserve the semantics while being efficient for the agent.</p>



<p class="wp-block-paragraph"><strong>How about the third example?</strong></p>



<p class="wp-block-paragraph">The third example is completely different again.</p>



<p class="wp-block-paragraph">Someone close to me needed to practise mathematics, and I thought: why don&rsquo;t we build a small learning app?</p>



<p class="wp-block-paragraph">It covers addition, subtraction, multiplication, division and division with remainder for grades one through four. But I did not want to build another simple quiz application. Together with Copilot, I researched learning approaches such as spaced repetition, immediate feedback, adaptive difficulty, motivation, cooperative learning and gamification without dark patterns.</p>



<p class="wp-block-paragraph">Interestingly, during that research Copilot challenged one of my original assumptions. I initially wanted the application to be generic for children everywhere. The research led us toward looking at the actual school curriculum instead. I realised that the order in which topics are introduced, the operations and number ranges differ enough that making it &ldquo;universal&rdquo; immediately was unnecessary.</p>



<p class="wp-block-paragraph">So we focused on Switzerland first and aligned the progression accordingly. Because Switzerland is multilingual, the application is available in German, French, Italian and English.</p>



<p class="wp-block-paragraph">It also has cooperative and competitive two-player modes, and when someone gets an answer wrong, the application explains one way to solve it and brings similar questions back through spaced repetition.</p>



<p class="wp-block-paragraph">I deliberately chose an architecture without a backend. There is no reason for me to collect children&rsquo;s personal data on a server, so the data stays on the device and the application can simply be hosted on GitHub Pages.</p>



<p class="wp-block-paragraph">What started as a small experiment is now being used and shared among friends. It accidentally became a little product.</p>



<p class="wp-block-paragraph">That experience showed me another side of Copilot: don&rsquo;t only use it to implement your solution. Use it as a sparring partner to <em>expand and challenge the solution space before you start building</em>.</p>



<p class="wp-block-paragraph"><strong>How do you typically use Copilot?</strong></p>



<p class="wp-block-paragraph">I actually don&rsquo;t use the classic Copilot autocomplete experience anymore.</p>



<p class="wp-block-paragraph">My work has moved almost completely toward agentic workflows.</p>



<p class="wp-block-paragraph">I use VS Code when I need a tight visual feedback loop&mdash;when I want to look closely at documents, code, presentations or intermediate results and adapt the process as I go.</p>



<p class="wp-block-paragraph">For larger execution-oriented tasks, I often work with the coding agent from the terminal. There I am more comfortable delegating a piece of work, letting it execute, and then inspecting the complete result. The interface I choose depends mostly on the feedback loop I need.</p>



<p class="wp-block-paragraph">I also had a fascinating experience using the coding-agent workflow through GitHub while travelling to JavaLand. I had started exploring an idea for a Maven plugin that optimises which Spring Boot auto-configurations are loaded. During roughly a four-hour journey, I was steering the agent from my phone: giving it a task, reviewing what it had done, thinking about the next step, and sending the next instruction.</p>



<p class="wp-block-paragraph">By the time I arrived, I had a working Maven plugin, a CI pipeline, performance tests against a sample application, and reports that could demonstrate whether the optimisation actually worked.</p>



<p class="wp-block-paragraph">That was the first time I had worked that way, and I was amazed that it actually worked. I wasn&rsquo;t trying to write Java on my phone. I was <em>reviewing, deciding and steering while the agent executed</em>.</p>



<p class="wp-block-paragraph">I also use MCP servers when they give me useful capabilities or context. For example, I have used Context7 for documentation, integrations with my Logseq knowledge base, and I have experimented with an MCP integration for Adobe Premiere Pro.</p>



<p class="wp-block-paragraph">But I don&rsquo;t use MCP just because I can. If a good CLI exists, I often prefer the CLI because it feels more direct and faster to me.</p>



<p class="wp-block-paragraph">The agent is also not a &ldquo;junior developer&rdquo; in my mental model. I think of it much more as a sparring partner. But just like anyone joining a project, it first needs to be brought up to speed.</p>



<p class="wp-block-paragraph">Context is king.</p>



<p class="wp-block-paragraph"><strong>Can you share some tips and best practices?</strong></p>



<p class="wp-block-paragraph">The biggest thing I would recommend is: <em>stop one-shot prompting.</em></p>



<p class="wp-block-paragraph">For anything non-trivial, I want to understand the problem before execution starts. Quite often I explicitly ask the agent to interview me first. The purpose of that interview is to uncover assumptions and expectations that are still implicit.</p>



<p class="wp-block-paragraph">A good agent can execute the wrong idea incredibly quickly. That does not make the detour cheaper.</p>



<p class="wp-block-paragraph">I experienced this myself while working on my Spring Boot auto-configuration optimiser. Initially I wanted to support both Spring Boot 3.5 and 4.x. There were architectural differences, so we implemented both approaches. Later I realised I no longer needed the 3.5 path and removing it was painful.</p>



<p class="wp-block-paragraph">The lesson was simple: <em>detours are expensive. Get the requirements right before you accelerate.</em></p>



<p class="wp-block-paragraph">Once the intent is clear, I want a plan. When I review that plan, four things matter especially to me: are assumptions visible, are verification gates defined, does the approach fit the architecture, and does it avoid unnecessary work?</p>



<p class="wp-block-paragraph">The second principle is to define <em>task-specific verification gates.</em></p>



<p class="wp-block-paragraph">&ldquo;Done&rdquo; should not mean that the model says it is done.</p>



<p class="wp-block-paragraph">For a refactoring, the gates might include passing tests, proving that all intended files were handled, updating documentation and leaving no TODOs behind. For the slide migration, the gates included screenshots, visual diffs, animations, PDF output and content completeness.</p>



<p class="wp-block-paragraph">The gates depend on the task. The principle does not: the agent should be able to provide evidence that the work satisfies the definition of done.</p>



<p class="wp-block-paragraph">I recently came across a skill called <code>unlazy</code> that follows a similar idea: create explicit gates, work through them deliberately, and prove that they have been completed rather than taking shortcuts.</p>



<p class="wp-block-paragraph">The third principle is to turn your lessons into <em>reusable skills</em>.</p>



<p class="wp-block-paragraph">I have started writing and maintaining my own Agent Skills. When I learn something from an execution&mdash;perhaps the agent misunderstood a convention, a useful check was missing, or I found a better way to approach a task&mdash;I update the skill.</p>



<p class="wp-block-paragraph">The next time I perform that task, the lesson is already there.</p>



<p class="wp-block-paragraph">One example is a skill I call <code>maintainer-audit</code>, inspired by work in the open agent skills community. I use it across my own repositories. It checks and, where appropriate, fixes the things I expect a maintained project to have: repository documentation, CI pipelines, Dependabot configuration, CodeQL, consistent cleanup and other project standards.</p>



<p class="wp-block-paragraph">The goal is not to generate another audit report for me to read. It brings the repository back toward the baseline I want automatically. That makes my projects more consistent and easier to maintain.</p>



<p class="wp-block-paragraph">I think of these skills as <em>living engineering knowledge</em> rather than static prompts.</p>



<p class="wp-block-paragraph">The fourth principle is to put deterministic engineering tools around the probabilistic model.</p>



<p class="wp-block-paragraph">I have my own quality harness that wraps tools such as Checkstyle, PMD and Spring Modulith architecture checks and produces a consolidated report that the agent can consume. I can run that from hooks and let the agent iterate:</p>



<p class="wp-block-paragraph">change &rarr; execute checks &rarr; read findings &rarr; fix &rarr; execute again.</p>



<p class="wp-block-paragraph">It continues until there are no findings left.</p>



<p class="wp-block-paragraph">That does not mean I stop looking at the software. I still run the application, interact with it and decide whether it behaves and looks the way I expect. Sometimes I deliberately implement feature by feature because the feedback loop is much tighter.</p>



<p class="wp-block-paragraph">I learned that asking for everything at once because &ldquo;the AI can do it&rdquo; is usually a bad idea. Large, generic specifications create large, generic implementations&mdash;and cleaning them up afterwards can be harder than building smaller increments correctly.</p>



<p class="wp-block-paragraph">More broadly, I think we developers need to talk much more about <em>how</em> we use these tools. Share the experiments that worked. Share the ones that didn&rsquo;t. Borrow ideas from each other and adapt them to your own context instead of looking for one universal AI development process.</p>



<p class="wp-block-paragraph">That is also why I like the idea of AI as a sparring partner. On a Friday night, when I want to experiment with something and no human pair is available, I suddenly have somebody&mdash;or something&mdash;I can challenge an idea with, review an approach with, or use as a very sophisticated rubber duck.</p>



<p class="wp-block-paragraph">But I still take those ideas back to real people. Human feedback, product understanding and real-world context remain essential.</p>



<p class="wp-block-paragraph"><strong>How do you think AI is changing our profession?</strong></p>



<p class="wp-block-paragraph">I don&rsquo;t think software engineering students should primarily aspire to become code-producing machines. They need to become strong problem solvers. They need to understand users and stakeholders, discover the real problem behind a requirement, challenge assumptions, understand products and markets, make architectural trade-offs, think critically, work in a structured way and transfer useful solutions from one context into another.</p>



<p class="wp-block-paragraph">The model is extraordinarily good at generating possibilities and executing things. But as a human, I usually know much more of the actual context&mdash;including the things nobody ever documented.</p>



<p class="wp-block-paragraph">So I want to remain in charge of shaping the solution and let the agent take over more of the execution.</p>



<p class="wp-block-paragraph">In that sense, I think <em>AI is putting the engineering back into software engineering</em>.</p>



<p class="wp-block-paragraph">And I like that.</p>



<h2 class="wp-block-heading" id="frank-delporte">Frank Delporte</h2>



<p class="wp-block-paragraph">GitHub profile: <a href="https://github.com/FDelporte">@FDelporte</a></p>



<p class="wp-block-paragraph"><strong>How did you get started in tech?</strong></p>



<p class="wp-block-paragraph">I&rsquo;ve been fascinated by computers since I got a Commodore 64 when I was 11. Took some side steps into video production and television work after school but turned back into coding as that video needed to be put on DVD and the very first websites&hellip; Yes, I&rsquo;m that old ;-).</p>



<p class="wp-block-paragraph"><strong>How has GitHub Copilot helped you recently?</strong></p>



<p class="wp-block-paragraph">It&rsquo;s a perfect companion to evaluate pull requests and investigate bug reports.</p>



<p class="wp-block-paragraph">One remarkable story is about the <a href="https://www.pi4j.com/">Pi4J library</a> that lets you build Java applications to interact with electronic components on the Raspberry Pi. In February 2026, we released V4 which has a new plugin using the Foreign Function &amp; Memory API. We tested it thoroughly before releasing, but still, shortly after the release someone <a href="https://github.com/Pi4J/pi4j/issues/622">reported that using 5 input buttons doesn&rsquo;t work as expected</a>. Pushing one of the first four configured buttons triggers a code execution as expected, while nothing happens with the fifth button.</p>



<p class="wp-block-paragraph">This is the kind of report you don&rsquo;t want to get. Nothing was visibly broken. No exception, no warning in the logs, the fifth button was simply silent. And it got worse: with the older gpiod plugin, the exact same hardware and the exact same application, worked fine. So the problem was in our new FFM code, which sits on top of the Linux kernel&rsquo;s GPIO character device and talks to it through native calls. That is not the part of the codebase where you expect to find a quick answer.</p>



<p class="wp-block-paragraph">So I assigned the issue to the Copilot coding agent and gave it two file paths as a starting point, the provider class and FFMDigitalInput. About half an hour later there was a pull request, with an explanation I really did not expect.</p>



<p class="wp-block-paragraph">Each input runs an event watcher that blocks in a native <code>poll()</code> call, waiting for the kernel to report a change on its GPIO line. Those watchers ran in virtual threads. And a virtual thread that blocks inside a native call cannot be unmounted from its carrier thread. It stays pinned there for the whole duration of the call. A Raspberry Pi 4 has four cores, so the virtual thread scheduler has four carrier threads. Register four inputs, and all four carriers are parked in <code>poll()</code> forever. The fifth watcher is created, but is never scheduled. That is exactly the bug that was reported. Not &ldquo;events are flaky&rdquo;, but &ldquo;the fifth one does nothing.&rdquo;</p>



<p class="wp-block-paragraph">What I liked most was not the diff, it was the conversation that followed in the review. I left a comment asking Copilot to explain this in more detail:</p>



<p class="wp-block-paragraph"><em>I thought the goal of virtual threads was exactly to step away from the platform thread limit? So how is this a problem that four virtual threads block the four threads on a four-core processor like the Raspberry Pi?</em></p>



<p class="wp-block-paragraph">Check the <a href="https://github.com/Pi4J/pi4j/pull/623">pull request for the full conversation</a>. Copilot was able to link the use of the Raspberry Pi which has four CPU cores with the reported problem. It was able to propose a simple fix for the problem, plus some extra improvements it found during its investigation.</p>



<p class="wp-block-paragraph"><strong>Can you share some tips and best practices?</strong></p>



<ul class="wp-block-list">
<li><strong>Tell it where to look:</strong> For the Pi4J issue #622, I added two file paths. That is a tiny bit of effort that removes a huge amount of searching in a large codebase. You usually have a hunch about the neighbourhood even when you have no idea about the bug. Give it to the tool so it doesn&rsquo;t need to investigate the complete code.</li>



<li><strong>Ask for proof and tests:</strong> &ldquo;Add a unit test to validate the change&rdquo; is something I ask a lot these days. Well, asked, because it has now become a rule in my instructions file. It also prevents cases where the diagnosis was wrong, because the test won&rsquo;t fail on the old code.</li>



<li><strong>Ask why:</strong> If you don&rsquo;t understand a fix, say so and ask. The explanation is a deliverable too and should be added into your project documentation or inside the ticket or pull request. It teaches everyone who reads the info later. For example, this also triggered more questions within the Pi4J team about virtual thread pinning on native calls.</li>



<li><strong>Stay in control:</strong> All of these pull requests in Pi4J were reviewed and approved by maintainers before they went in. That&rsquo;s the model that works best in this project: the agent does the investigation, the humans stay responsible for what ships. But also for my other projects I always do a review of the code that was generated by the tool. I always want to keep code readable and maintainable. Too often, a tool creates duplicate methods or recreates something which is already available in another place and should be combined. That&rsquo;s your responsibility. You can go very fast these days with AI-assisted coding, which also means you can very fast create a mess. Don&rsquo;t do that, keep your code manageable, your colleagues and future-self will thank you if they have to investigate bugs or make improvements later.</li>
</ul>
